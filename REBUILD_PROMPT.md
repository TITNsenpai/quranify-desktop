## 0. What the app is

A very light Windows app with two parts:

1. **Site mode:** shows the existing website https://quranify.pro (a commercial Quran-listening site owned by Media Content Labs, LLC) in a borderless-feeling native window, with no browser chrome. It must look and behave exactly like the site in a browser. The app is not affiliated with the site's owner, and must say so.
2. **Offline mode:** a full Quran-listening app built only on free, open sources. It has 244 reciters with all their riwayat, from mp3quran.net. You can download and play without internet, read the Mushaf text with tafsir, run a khatma plan, and use a memorization trainer.

Plus system-level features: tray icon, single instance, global hotkeys, a mini player, auto-pause (on lock, calls, or headphones unplugged), a sleep timer, a daily khatma reminder notification, autostart, an installer and an uninstaller.

The #1 non-functional requirement: **"light as a feather"**. Minimal RAM and CPU when idle, a tiny binary (~2 MB), and no Electron or bundled browser.

- **Audio endpoints:** `windows` 0.62 (Win32_Media_Audio, Win32_System_Com), for IMMDeviceEnumerator.

- **Icon and version info:** `winresource` as a build dependency. Embed `icons/icon.ico` as resource id 1; ProductName "Quranify Desktop", FileDescription "Quranify".
- **Release profile:** `opt-level="s"`, `lto=true`, `codegen-units=1`, `panic="abort"`, `strip=true`.
- **No console window in release:** `#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]`.

- **Build script `build-release.ps1`:** builds both, in order, into `dist/`, and prints their sizes. Set `CARGO_TARGET_DIR` to a short path such as `C:\Users\<user>\.cargo\qd-target`. Long paths break the MSVC linker with LNK1104.
- **The offline UI:** one self-contained HTML file (`ui/offline.html`, vanilla JS, no frameworks, no CDN). `ui/site.js` is the script injected into the site; `ui/mini.html` is the mini player. All three are embedded with `include_str!`. The Quran font is an Arabic-subset woff2 embedded with `include_bytes!`.

## 3. Architecture

- **Main window:** one tao window, title "Quranify", dark theme, default 1280×800, minimum 960×600. It holds one wry WebView.
- **WebView profile and data folder:** a persistent WebView2 user-data folder at `%LOCALAPPDATA%\QuranifyDesktop\WebView2`, so the site login survives restarts. All app data lives in `%LOCALAPPDATA%\QuranifyDesktop`. Use the known-folder/env path, and make sure non-ASCII (e.g. Arabic) user names work.
- **WebView2 browser arguments:**
  - `--autoplay-policy=no-user-gesture-required` (needed so hotkeys and tray can start playback; the site doesn't autoplay on its own),
  - `--enable-features=HardwareMediaKeyHandling`,
  - `--disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection,msEdgeTranslate,msShoppingExp,msEdgeSidebarV2`,
  - `--disable-background-networking --disable-component-update --disable-sync --no-first-run`,
  - `--disable-gpu`, unless the "GPU" setting is on.
  - Env var `QURANIFY_ARGS`, appended (used for `--remote-debugging-port` in testing).
  - Every WebView that shares the profile (main and mini) must use **identical** arguments, or creation fails.
- **Custom protocol `qoff`:** async, served at `http://qoff.localhost/`.
  - `/` serves the offline page.
  - `/font/quran.woff2` serves the font.
  - `/audio/{moshafId}/{n}.mp3` serves downloaded files, with HTTP Range support in 2 MB chunks so seeking works.
- **IPC:** pages call `window.ipc.postMessage(JSON)`. Rust replies by evaluating `window.__qo && window.__qo.on({...})` in the page.
- **Event loop:** `EventLoopProxy<UserEvent>`.
  - Gotcha: when sending from a callback that runs on the main thread (WebView2 COM callbacks), the event isn't processed until the next window message. Use a `post()` helper: when it's called on the main thread, it sends from a short-lived helper thread.
- **Navigation:**
  - Internal hosts stay in-app: quranify.pro, qoff.localhost, `about:`, `data:`, `blob:`, and auth hosts (accounts.google.com, appleid.apple.com, `*.firebaseapp.com`, `*.googleapis.com`, and `/__/auth/` paths).
  - Every other link opens in the default browser.
  - Auth popups (Google/Apple sign-in) open as real child popups, so sign-in completes.
  - Site links with `target=_blank` that point to quranify.pro open in the same window.
- **Remember the last page:** remember the last site URL (`last_url.txt`) and reopen it.
- **Offline auto-switch:** if site navigation fails with a network error (CANNOT_CONNECT, HOST_NAME_NOT_RESOLVED, DISCONNECTED, TIMEOUT, CONNECTION_RESET/ABORTED, SERVER_UNREACHABLE), switch to the offline page by itself. The site script also switches 4 s after the browser goes offline.
- **Graceful shutdown:** on quit, hide the window, close the WebView, and wait for WebView2's `BrowserProcessExited` (5 s fallback) before exiting. Otherwise cookies and localStorage may not be flushed and the user gets logged out.

### 4.8 Khatma (complete the Quran in N days)
- Choose the number of days: 3, 7, 10, 15, 20, 30, 60, 90, 365, or a custom number from 3 to 604. Choose the mode: reading or listening. Choose a reciter (only recitations with verse timings and 114 surahs).

  - If 240 % N == 0 → hizb quarters, grouped.
  - Otherwise → pages.
  - Day k covers units `[floor(k·L/N), floor((k+1)·L/N))`.
  - **Verify** in a unit test that for N in {3, 7, 10, 13, 15, 30, 40, 60, 365, 604} the days are contiguous, cover 1:1 to 114:6 with no gaps or overlaps, and that day 2 of 30 is exactly 2:142–2:252.

- **Read:** the reader panel shows a verse range that may span several surahs, with a surah heading at each start and a "خلّصت الورد" button at the end.
- **Listen:** a queue of segments `{m, n, a0, a1, seg:true}`. Seek to the start of a0 once metadata and timings are ready, and stop at the end of a1 with a 50 ms precision timer (not `timeupdate`). At the end of the last segment, mark the day done.

- **Library banner:** "وردك النهارده" with Read/Listen.
- **Stored in user.json:** `khatma = {start, startDay (local day number = Date.UTC(y,m,d)/864e5), days, mode, reciter, done:{dayIndex: timestamp}, labels:[one human label per day]}`. The labels exist so that Rust can write the notification without recomputing portions.

### 4.11 Auto-pause
- **Lock:** a hidden top-level window (not message-only, or broadcasts are missed) registers `WTSRegisterSessionNotification`. Lock pauses playback; unlock resumes it.
- **Sleep:** `PBT_APMSUSPEND` pauses.
- **Audio output changes** (headphones unplugged): poll the default render endpoint id (IMMDeviceEnumerator) every 2 s. Pause and show a toast explaining why.
- **Calls:** detect another app using the microphone from `HKCU\Software\Microsoft\Windows\CurrentVersion\CapabilityAccessManager\ConsentStore\microphone` (and the `NonPackaged` subkey). An entry with `LastUsedTimeStart>0 && LastUsedTimeStop==0` is in use now; ignore entries whose name contains quranify or msedgewebview2. Pause during the call and resume after it.
- **Cost:** polling runs **only** while something is playing or was paused by us (an atomic flag).
- **Ownership:** resume only if *we* paused it. If the user pressed pause, never resume. If the user presses play during a call, don't pause again.
- **Settings:** each trigger has its own switch, plus "auto-resume".
- **`--diag` CLI:** writes `diag.txt` with the current output id and mic-in-use state.

### 4.12 Daily khatma reminder

- **Cost:** a 60-second clock check. `user.json` is read only after the reminder time. Remember the last reminded day in `reminded.txt`, so it fires once a day, including on startup if the time already passed.
- The khatma page has a switch, a time input and a "جرّب" (test) button.

## 5. Known pitfalls (these were real bugs; avoid them)
1. **Main-thread event posting:** `EventLoopProxy::send_event` called from WebView2 callbacks on the main thread stalls until the next message. Post from a helper thread.
2. **Mini webview creation:** it fails unless its browser arguments exactly match the main one's, since they share the profile.
3. **Autoplay policy:** without `--autoplay-policy=no-user-gesture-required`, play from the tray or a hotkey is silently blocked.
4. **Duplicated Basmala:** alquran.cloud puts the Basmala inside verse 1.
5. **Login lost:** if you exit before the WebView2 browser process ends, the site login is lost.
6. **Uninstall quoting:** Rust escapes quotes in `cmd /C` arguments, so use `raw_arg`.
7. **Bidi in mixed text:** wrap mixed LTR/RTL fragments such as "3 MB" in `<bdi dir=ltr>`. Don't put "·" next to Arabic-Indic digits, because it looks like ٠ (zero); use "،".
8. **CSS class collisions:** e.g. naming a day-grid state `.sel` while `.sel` styles `<select>`.
9. **Wrong UI tests:** a minimized window pauses page timers and animations, so menus "don't work" in tests. Test with the window restored.
10. **Message-only windows:** they don't receive session or power broadcasts; use a hidden top-level window.
11. **Tray icon id:** see 4.12 (the id isn't 1, and don't use a GUID).
12. **Store-Python sandbox:** Microsoft-Store Python virtualizes `%LOCALAPPDATA%`. Use Node or PowerShell to inspect app data during tests.
13. **Shortcuts with Arabic paths:** don't create shortcuts with PowerShell/WScript.Shell. It can't save paths with characters outside the system code page (e.g. an Arabic user name on English Windows), and hidden PowerShell windows make antivirus suspicious. Use `IShellLinkW` + `IPersistFile` with `SHGetKnownFolderPath(FOLDERID_Programs / FOLDERID_Desktop)`.
14. **Silent crashes:** a release build with no console and `panic=abort` closes silently on any panic. Install a panic hook that writes `crash.txt` (version, message, backtrace) and shows an Arabic message box saying where the file is. If the WebView fails to build (WebView2 runtime missing), show an Arabic Yes/No box offering https://go.microsoft.com/fwlink/p/?LinkId=2124703.
15. **Off-screen windows:** if the saved window position (or the mini player's) is on a monitor that's no longer connected, centre it on the current monitor.
